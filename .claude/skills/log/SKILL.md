# 오늘 하루 기록

오늘 AI에게 맡긴 작업을 `docs/위임로그/<본인>.md`에 작업 단위로 기록한다. 작업 하나마다 목표·프롬프트·결과·검증·수정·배운점 6칸을 채운다.

## 1. 본인 문서 찾기

`git config user.name`으로 파일을 고른다.

| git user.name | 문서 |
|---|---|
| elvinleeys | lys.md |
| HAN GaYeong | hgy.md |
| shinseonyi | ssi.md |
| junhyunu | jhw.md |

표에 없으면 `docs/위임로그/`의 파일 목록을 보여주고 본인 문서를 물어본 뒤, 답을 받으면 이 표에 한 줄 추가한다.

## 2. 오늘 한 일 모으기

오늘 날짜(로컬 기준) 작업만 모은다.

- `git log --all --since=midnight --author="<user.name>" --stat` : 오늘 커밋
- `git status --short`, `git diff --stat` : 아직 커밋하지 않은 작업
- 현재 대화에서 구현하거나 해결한 내용

모은 내용이 없으면 기록하지 말고 "오늘 기록할 작업을 찾지 못했어요"라고 알린 뒤, 직접 불러줄 내용이 있는지 묻는다.

## 3. 문서에 쓰기

기록은 날짜별 섹션(`## YYYY-MM-DD`)으로 나누고, 날짜 순서대로 문서 아래쪽에 쌓는다. 기존 내용은 수정·삭제하지 않는다.

- 오늘 날짜 섹션이 없으면 문서 맨 아래에 새로 만든다.
- 오늘 날짜 섹션이 있으면 새로 만들지 말고 그 섹션에 빠진 작업만 덧붙인다.
- 중복 판단: 오늘 섹션에 같은 작업(같은 기능·같은 문제)이 이미 있으면 표현이 달라도 추가하지 않는다. 같은 작업에 새 내용이 생긴 경우만 별도 작업으로 쓴다(예: "PDF 업로드 구현"이 있을 때 "PDF 업로드 용량 제한 추가").
- 중복 판단은 같은 날짜 안에서만 한다. 다른 날짜에 같은 기능을 이어서 작업했다면 그날 섹션에 기록한다.

```markdown
## YYYY-MM-DD

### <작업 이름>
- 목표: <무엇을 하려 했나>
- 프롬프트: <AI에게 맡긴 핵심 지시>
- 결과: <무엇이 나왔나 (파일·기능 이름 포함)>
- 검증: <어떻게 확인했나 (테스트, 실행, 직접 확인 등)>
- 수정: <무엇을 고쳤나, 무엇을 직접 했나, 그 이유>
- 배운점: <한 줄>
```

- 작업 하나 = `### <작업 이름>` 소제목 하나. 6칸은 순서대로 모두 쓰고, 각 칸은 1~2줄로 군더더기 없이.
- 프롬프트는 대화의 실제 지시에서 핵심만 옮긴다. 지어내지 않는다.
- 검증하지 않았으면 `검증: 안 함`, 고친 것·직접 한 것이 없으면 `수정: 없음`.
- 해결하지 못한 작업은 `결과:`에 `미해결 - <막힌 곳>`으로 쓴다.
- 추측으로 칸을 채우지 않는다. 근거(커밋, 변경, 대화)가 없는 칸은 `확인 안 됨`으로 둔다.

## 4. 마무리

추가한 내용을 사용자에게 그대로 보여준다. 커밋·푸시는 사용자가 요청할 때만 한다.
