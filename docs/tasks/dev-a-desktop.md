## 작업 목록
- [ ] A1. Electron 프로젝트 세팅 — 빌드 도구를 먼저 정한다 [확인 필요]
- [ ] A2. 로그인: 127.0.0.1 임시 서버 → 브라우저로 웹 로그인 → 콜백으로 일회용 코드 수신 → PKCE로 토큰 교환 → 임시 서버 종료
  - 웹 담당 B2(로그인 페이지, 콜백 이동)와 맞물림. 넘기는 값의 형식은 둘이 먼저 합의
- [ ] A3. 항상 위에 떠 있는 우주 비행사 캐릭터 창
- [ ] A4. 끌어다 놓기 수집: 브라우저 주소(URL·영상 링크), 이미지, 파일
- [ ] A5. 올리기 전 검사: 지원 형식(csv, txt, md, jpeg, jpg, png, svg, HTML, PDF), 10MB
- [ ] A6. 캐릭터 메뉴: 클립보드 붙여넣기, 메모, 화면 캡처, 파일선택, 웹 열기, 앱 종료
- [ ] A7. packages/shared/src/collect 수집 함수 (기록 생성 → 업로드 → 완료 알림) + Vitest 테스트
- [ ] A8. 저장 결과 표시: 캐릭터 옆 말풍선 (올리는 중, 업로드 완료, 가공 완료, 형식·크기 오류, 저장 실패, 가공 실패)
- [ ] A9. 저장 창: 그룹 선택 ('분류 안 된 기록' 기본, 다른 그룹 고르기, 새 그룹 만들기. AI 추천 없음), 출처 주소 선택 입력

## 다른 담당과 맞물리는 곳
- 웹 B3의 수집 API가 있어야 실제 저장이 된다. API 완성 전에는 함께 정한 요청·응답 타입으로 개발한다
- 저장 창은 웹 기록 넣기 창(B8)과 같은 그룹 목록 조회, 새 그룹 만들기를 쓴다. 웹 화면만이 아니라 앱에서도 부를 수 있는 API로 열려 있어야 한다 (웹 담당과 합의)
- 가공 완료·실패를 말풍선으로 알리려고 기록의 처리 상태를 3초마다 조회한다. 기록 하나의 상태를 돌려주는 API가 필요하다 (웹 담당과 합의)
