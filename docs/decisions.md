# 결정 기록

구조나 기술을 바꾸기 전에 아래 결정과 이유를 먼저 확인한다. 바꾸게 되면 새 줄을 추가하고 기존 줄은 지우지 않는다.

| 날짜 | 결정 | 이유 |
| --- | --- | --- |
| 2026-11-26 | npm workspaces 모노레포 (apps/desktop, apps/web, apps/worker, packages/*) | 데스크톱·웹이 타입과 수집 함수를 함께 쓰기 위해 |
| 2026-11-26 | 데스크톱 앱은 수집 전용, 웹은 수집 + 찾기 | 데스크톱은 작업 중 빠른 저장에 집중 |
| 2026-11-26 | 가공은 Flask 서버 (apps/worker) | Python 문서 처리·OCR 도구 활용, 서버리스 실행 시간 제한 회피 |
| 2026-11-26 | 웹 서버 API가 Flask에 가공 요청 전달 + Flask 주기적 재처리 | 입구를 하나로 유지, 전달 누락 복구 |
| 2026-11-26 | 일반 데이터는 Supabase DB, 원본 파일은 Supabase Storage, 벡터는 Qdrant | DB 용량을 메타데이터에 쓰고 벡터 용량 여유 확보 |
| 2026-11-26 | Supabase DB가 기준, Qdrant는 재생성 가능한 색인 | Qdrant 무료 클러스터는 오래 안 쓰면 삭제될 수 있음 |
| 2026-11-26 | Supabase 인증의 구글 로그인 | 팀 결정 |
| 2026-11-26 | 데스크톱 로그인은 로컬 주소로 돌려받기 + PKCE | 팀 결정 |
| 2026-11-26 | 지원 파일: csv, txt, md, jpeg, jpg, png, svg, HTML, PDF. 이미지는 OCR, 영상 링크는 자막·음성을 글로 변환 | 팀 결정 |
| 2026-11-26 | 파일 1개 10MB 제한 | Storage 무료 용량 1GB를 조직이 공유, 큰 파일은 가공 시간·AI 비용 증가 |
| 2026-11-26 | Storage 원본: 출처 링크가 있는 파일만 가공 성공 후 삭제, 출처 링크가 없는 파일은 유지, 실패한 파일은 유지 | Storage 무료 용량 절약. 출처 링크가 없는 파일은 Storage가 유일한 사본이고 벡터로 원본을 되살릴 수 없음 |
| 2026-11-26 | URL·영상 링크 원문 글은 저장하지 않음 (A안). 원문 조각 벡터는 관련 기록 찾기용 | PRD 4-5 원칙, 무료 용량. 원문 조각 글 DB 저장(C안)은 고도화 항목 |
| 2026-11-26 | 요약본 벡터 + 원문 조각 벡터를 모두 Qdrant에 저장 | 요약으로 대략 찾고, 원문 조각으로 세부 내용이 있는 기록을 찾기 위해 |
| 2026-11-26 | 챗봇은 Next.js 서버에서 처리 | 응답 속도 기대 |
| 2026-11-26 | 그룹은 별도 테이블, 기록은 그룹 하나를 참조 | 이름 변경, 행성 색상, 빈 그룹 생성 지원 |
| 2026-11-26 | AI가 기존 그룹을 추천해 기본값으로, 새 그룹 이름도 추천. 사용자가 변경 가능 | PRD 원칙 1, 팀 결정 |
| 2026-11-26 | 원래 맥락(저장 이유 메모)은 선택 입력 | PRD 원칙 4 |
| 2026-11-26 | 재발견 기록과 추가 메모를 '재발견 메모' 하나로 통합 | 둘 다 기록에 날짜별로 쌓이는 글 |
| 2026-11-26 | 연결은 두 기록을 잇는 방식. AI가 후보 추천, 사용자가 수락·거절 | 별자리 컨셉과 일치 |
| 2026-11-26 | 그룹 삭제: 빈 그룹은 바로, 기록이 있으면 옮기기/모두 삭제를 묻고 진행 | 팀 결정 |
| 2026-11-26 | 개발 분담: 데스크톱 앱 1명, 웹(Flask 포함) 1명 | 팀 결정 |
| 2026-11-26 | user 테이블에 display_name, avatar_url, email을 선택 칸으로 추가. 구글 정보를 트리거로 복사, 표시 이름은 구글 이름 그대로 | 화면 표시용. 실제 사용자 전이라 나중에 필요 없으면 삭제 |
| 2026-11-26 | 가공 서버 프레임워크를 Flask에서 FastAPI로 변경 (이전 줄의 'Flask'는 이 결정 이후 FastAPI로 읽는다) | 웹 서버와의 요청 형식을 Pydantic으로 명확히 하고 /docs로 공유, 외부 API 호출이 많아 비동기 처리에 유리 |
| 2026-11-26 | 그룹 단위 '챗봇·MCP 검색 제외' 설정 추가 (ai_search_excluded). 웹 챗봇과 MCP 찾기에만 적용, 가공·연결 추천·AI 그룹 추천은 그대로. '분류 안 된 기록'도 설정 가능 | 사용자가 정한 그룹을 챗봇과 외부 AI 검색에서 빼기 위해 |
| 2026-11-26 | 챗봇·MCP 검색 제외는 Qdrant payload에 group_id를 저장하고 검색할 때 제외 그룹 목록으로 거른다. 기록 그룹이 바뀌면 payload도 갱신 | Qdrant 안에서 걸러 결과 개수가 줄지 않고, 거르기 누락 위험이 작음 |
| 2026-11-26 | 표시 이름은 처음엔 구글 이름, 사용자가 설정에서 변경 가능. 가입 후에는 구글 정보로 display_name을 덮어쓰지 않음 (avatar_url, email은 계속 갱신) | 사용자가 바꾼 이름 유지 |
| 2026-11-27 | 데스크톱 캐릭터 메뉴는 클립보드 붙여넣기, 메모, 화면 캡처, 파일선택, 웹 열기, 앱 종료 | 앱은 수집 전용. 찾기는 웹 열기로 넘긴다 |
| 2026-11-27 | 데스크톱에서 선택한 글은 끌어다 놓기가 아니라 클립보드 붙여넣기로 받는다. 끌어다 놓기는 파일, 이미지, 브라우저 주소만 받는다 | 복사 후 붙여넣기가 익숙한 동작 |
| 2026-11-27 | 데스크톱은 놓거나 메뉴로 넣으면 바로 저장하지 않고 그룹을 고르는 저장 창을 띄운다. AI 추천 그룹이 기본, 다른 그룹 선택과 새 그룹 만들기 가능 | 저장할 때 분류까지 끝내기 위해 |
| 2026-11-27 | 데스크톱 저장 결과는 캐릭터 옆 말풍선으로 알린다. 업로드 완료와 가공 완료를 각각 알리고, 형식·크기 오류와 저장·가공 실패도 말풍선으로 알린다 | 별도 창이나 OS 알림보다 작업 흐름을 덜 끊는다 |
| 2026-11-27 | 데스크톱은 저장한 기록의 처리 상태를 3초마다 웹 서버에 조회한다 (최대 2분). Supabase 실시간 알림은 쓰지 않는다 | 앱은 웹 서버 API를 거친다는 구조를 그대로 따르고, 기록 한두 개의 상태 확인에 실시간 설정은 과함 |
| 2026-11-27 | 데스크톱 저장 창은 '분류 안 된 기록'으로 바로 띄우고, AI 추천이 2초 안에 오면 선택을 바꾼다. 사용자가 이미 고른 그룹은 바꾸지 않는다 | 추천을 기다리느라 저장이 늦어지지 않게 |
| 2026-11-27 | 데스크톱에서 클립보드로 넣은 글의 출처 주소는 저장 창의 선택 입력으로 받는다. 비워도 저장한다 | 클립보드에는 페이지 주소가 항상 들어 있지 않음 |
