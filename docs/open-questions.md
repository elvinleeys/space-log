# 확인 필요 (미결 목록)

구현 중 아래 항목을 만나면 추정하지 말고 사용자에게 선택지를 주고 물어본다. 결정되면 이 목록에서 지우고 docs/decisions.md에 한 줄을 추가한다.

## 먼저 정할 것 (데이터·서버 구성에 영향)
- PRD 작성자 확인: PRD 5번 '저장하면 AI가 요약'을 'AI 분석하기 버튼·챗봇 요청 때 요약'으로 바꾸는 것 (2026-11-28 디자인 싱크)
- AI 분석 결과를 기다리는 방식 (상태 조회 반복, Supabase 실시간 알림), 분석 실패 안내 문구
- 챗봇: FAQ 목록과 문구, '기록으로 저장' API와 chat 기록 제목
- 데스크톱 말풍선 '받았어요! 정리하고 있어요'(screens/01): 저장 때 AI 요약을 하지 않으므로 문구 조정 필요 (데스크톱 담당)
- PRD 작성자 확인: 원칙 1과 R3의 '추천 그룹 미리 선택'을 'AI 추천 버튼(누르면 업로드·가공 후 파일 내용 + 메모로 추천) + 가공 후 추천'으로 바꾸는 것, PRD 4-5·155행의 출처 링크 문구를 '있으면 함께 저장'으로 맞추는 것
- 실패한 기록 삭제를 다시 시도하는 주체 (가공 서버의 주기 작업, 웹 서버)
- Storage 파일을 보여 주는 방식 (공개 주소, 기한이 있는 서명 주소)
- 재발견 메모를 Qdrant 색인에 포함할지 (재발견 메모 UI를 정한 뒤)

## 화면·동작
- 관련 기록이 제외 그룹에만 있을 때 알려 줄지
- 가공 서버의 백그라운드 실행 방식과 동시 처리 개수 (BackgroundTasks, 프로세스 풀, DB queued 대기열)
- 구글이 이름을 주지 않았거나 이메일로 가입했을 때 사이드바에 보일 값
- 표시 이름 길이와 빈 값 규칙
- 출처 링크 파일의 원본 삭제 후 file_path를 비울지, 삭제 시각을 따로 남길지
- 데스크톱: 브라우저 로그인을 끝내지 않았을 때 처리, 토큰 보관, Electron 빌드 도구, macOS에서 클립보드의 출처 주소를 읽을 수 있는지
- 기록 넣기: AI 추천 실패 안내 문구
- 첫 로그인 후 안내 화면 유무
- 검색: 검색 범위(파일 본문 포함 여부), 의미 검색 사용 여부, Space 결과 0개 안내
- 그룹: '마지막 그룹'에 '분류 안 된 기록'을 세는지, 빠른 분류 카드에 AI 추천을 표시하는 방식
- 재발견 메모: UI 미정 (입력 위치, 표시 방식, 수정·삭제 허용)
- 함께 볼 만한 기록: 삭제·직접 연결 허용 여부
- 챗봇: 사용법 질문 처리, 처리 중 기록 포함, 파일 원문 조각 글 사용, 묶음 분석 답 형식, 긴 답 기준
- 설정 이름: 사용자에게 보이는 이름은 'AI가 읽지 않는 그룹'으로 통일 (개발 문서의 '챗봇·MCP 검색 제외'와 같은 설정)
- 챗봇 못 찾음 안내: 'AI가 읽지 않는 그룹'이 있을 때만 "AI가 읽지 않도록 설정한 그룹이 있어서 찾지 못했을 수 있어요. 챗봇 설정을 확인해 주세요." 안내와 챗봇 설정 바로가기 버튼을 보여 주는 제안 (확정 아님, 개발 검토 중. 시안은 ssi가 미리 만들 예정). 그 그룹에 실제로 맞는 기록이 있는지는 판단하지 않고 사용자에게 맡긴다
- 'AI 분석하기' 버튼과 'AI가 읽지 않는 그룹': 이 그룹의 기록에서는 버튼을 비활성화하고 "AI가 읽지 않는 그룹의 기록이에요." 안내를 보여 주는 제안 (확정 아님, 개발 검토 중). 지금 설정은 챗봇·MCP 검색에만 적용되므로 버튼까지 넓힐지 개발자 판단 필요
- 에러·로딩 등 예외 상황 화면: 점검 시안 대기 (ssi 담당)
- 링크: 원문을 가져올 수 없는 링크 처리, 자막이 없는 영상의 음성 변환 방법, 영상 길이 제한
- 지원하지 않는 형식이나 10MB를 넘는 파일의 안내 방식 (웹 기록 넣기 창. 데스크톱은 말풍선으로 결정)
- MCP: 인증 방식, 서버 위치, md 파일 가져오기 위치
- 3D 우주 라이브러리
- 연결 추천이 Qdrant를 읽는 위치

- 처리 중 기록 표시 방식, 모바일 Space 이동 방식
- 모아보기(여러 기록 모음)가 기존 연결(두 기록 잇기)과 같은 기능인지, 블랙홀(그룹 보관)이 '기간 지난 기록'과 같은지
- 로그인: 이메일 인증 메일 확인 여부, 비밀번호 찾기, 로그인 페이지 시안, 이메일 가입자의 표시 이름

## 예외 처리
- 저장 실패 (F2 웹 기록 넣기 창, F8), 로그인 실패 (F1), 가공 실패 재시도 (F4)
- 기록이 없거나 지워졌을 때 (F7), 검색 결과가 없을 때 (F6)

## P1 기능
- 연결: 후보 표시 위치, 추천 시점, 후보 개수와 비슷함의 기준, 거절 후보 재추천, 직접 연결 허용, 방향 유무
- 블랙홀: 기준일(저장한 날, 마지막으로 본 날), 알림 채널, 그대로 둔 기록의 재진입, 리마인드 기간 단위·기본값

## 고도화 항목 (MVP 이후)
- 원문 조각 글 저장 (C안): URL·영상 링크 원문을 조각 단위로 Supabase DB에 저장하고 Qdrant에는 벡터만 둔다. 세부 문장까지 근거로 답할 수 있고 재생성 때 원문을 다시 가져오지 않아도 된다. PRD 4-5 변경과 무료 DB 용량(프로젝트당 500MB) 검토 필요. chunk_index가 이미 저장되어 있어 확장 가능
