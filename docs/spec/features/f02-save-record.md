# F2. 기록 저장
담당: 웹(API, 기록 넣기 창) + 데스크톱(수집 캐릭터). 수집 함수는 packages/shared · 요구사항: R2

- **입력**: 정보 (메모 글, 하이라이트 문장, URL, 영상 링크, 파일, 캡처), 제목 (선택), 메모 (original_context, 선택. 메모·하이라이트의 본문은 information_content, 다른 형식에는 본문을 받지 않는다), 출처 주소 (선택), 그룹 (선택, 고르지 않으면 '분류 안 된 기록'), 수집 경로 (desktop, web, mcp). 지원 파일 형식은 csv, txt, md, jpeg, jpg, png, svg, HTML, PDF이고, 파일 1개는 10MB까지. 파일·캡처 기록은 파일을 여러 개(최대 10개, 합계 50MB) 넣을 수 있고 메모(original_context)도 함께 적을 수 있다. 10MB가 넘는 jpg·png는 올리기 전에 클라이언트가 줄인다(긴 변 4096px, JPEG 재압축)
- **처리**: 기록을 uploading 상태로 만든다. 파일 없는 기록(메모·하이라이트·URL·영상 링크)은 바로 queued로 만들고 가공을 요청한다. 제목을 비우면 서버가 채운다(메모 첫 줄, 주소). 파일 기록은 빈 제목을 저장하지 않고 화면에서 첫 파일 이름을 보여 준다. 파일은 Supabase Storage에 올리고 파일마다 record_file에 경로와 순서를 남긴다. 화면의 파일 이름은 '제목1, 제목2…'(파일 1개면 '제목', 제목이 없으면 원래 파일 이름). 모든 파일의 업로드 완료 알림을 받으면 queued로 바꾸고, 웹 서버가 가공 서버(FastAPI)에 자동 가공(글자 추출 + 원문 조각 벡터)을 요청한다. AI 분석은 저장 때 하지 않는다 (F4, 'AI 분석하기' 버튼)
- **출력**: 저장된 정보 기록 (처리 중)
- **예외**: 데스크톱은 지원하지 않는 형식, 10MB 초과, 업로드·저장 실패를 캐릭터 옆 말풍선으로 알리고, 저장 실패에는 다시 시도 버튼을 둔다 (screens/01-desktop-collector.md). [확인 필요: 웹 기록 넣기 창에서 지원하지 않는 형식이나 10MB를 넘는 파일을 넣었을 때의 안내 방식] [확인 필요: 웹 기록 넣기 창의 업로드·저장 실패 처리]
