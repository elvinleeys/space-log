# F4. 기록 가공·색인
담당: 웹 (apps/worker, FastAPI) · 요구사항: R4

- **입력**: queued 상태의 정보 기록, Storage 파일(record_file, 0~10개) 또는 URL·영상 링크·글
- **처리**: 가공 서버(FastAPI)가 형식별로 글자를 뽑는다. PDF, HTML, txt, md, csv는 글자를 그대로 뽑고, 이미지(jpeg, jpg, png, svg)는 OCR로 글자를 읽는다. 유튜브 같은 영상 링크는 자막이나 음성을 글로 바꾼다. 파일이 여러 개면 모든 파일의 글자(와 함께 적은 메모 글)를 합쳐 기록 하나에 AI 정리글 1개를 만든다. 원문 조각 벡터는 파일마다 만든다. AI API로 AI 정리글(한 줄 요약, 핵심 포인트, 자료 유형, 이럴 때 다시 보세요, 바로 써먹을 것, 키워드, 관련 직군 최대 2개, 직군 노트)을 만든다 (양식: docs/database.md). 요약본 벡터(한 줄 요약 + 핵심 포인트 + 이럴 때 다시 보세요)와 원문 조각 벡터를 만들어 Qdrant에 올린다. AI 정리글과 처리 상태는 Supabase DB에 저장한다. 하이라이트는 요약하지 않고 선택 문장 그대로 둔다
- **원문 처리**: 출처 링크(source_url)가 있는 파일은 가공 성공(done) 후 Storage 원본을 지우고 출처 링크로 본다. 출처 링크가 없는 파일(내 컴퓨터에서 올린 파일, 화면 캡처)은 원본을 유지한다. 가공에 실패한 파일은 지우지 않는다. URL·영상 링크의 원문 글은 저장하지 않는다. 원문 조각 벡터는 관련 기록을 찾는 데만 쓴다. 원문 조각 글 저장은 고도화 항목(C안)
- **출력**: 요약본, Qdrant 벡터, done 상태
- **예외**: 실패하면 failed 상태와 오류 내용을 남긴다. [확인 필요: 재시도 방식] [확인 필요: 원문을 가져올 수 없는 링크 처리. 인스타그램, 유료 기사] [확인 필요: 자막이 없는 영상의 음성 변환 방법, 영상 길이 제한]
