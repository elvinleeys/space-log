# Spacelog PRD

## 1. 개요

**한 줄 정의**
Spacelog는 흩어진 기록을 한곳에 쉽게 저장하고, 필요할 때 쉽게 찾게 해 주는 개인 기록 서비스다.

**컨셉**
"모두에게 자기만의 우주가 있다." 기록 하나하나가 별이 되고, 기록을 쌓아 자신만의 세계를 만든다.

**서비스 목표** `확정`
쉽게 기록하고, 쉽게 기록을 찾는다.

**풀려는 문제** `가설 · 설문으로 확인`
정보를 여러 곳에 저장하다 보니 어디에 뒀는지 몰라 다시 찾기 어렵다.

**설문 조사 후 확정** `가설 · 설문 뒤 결정`

저장 이후의 기록을 다시 활용하거나 정리할 수 있게 돕는다.

- **수집 PC앱/PWA 반응형 웹**: ****정보 매체, 유튜브, 인스타그램, 파일 기록 수집
- **검색/AI챗봇/리스트 확인**: 수집한 기록 확인
- **리마인드**: 잊고 있던 기록을 다시 만나게 한다.
- **연결**: 저장한 기록끼리 이어서 모아보고 새로운 기록을 남긴다.
(컨셉의 '별을 이어 별자리를 만든다'와 이어짐)

기능 형태와 구현 방법은 미정이다. 설문에서 아래를 확인한 뒤 정한다.

- 저장한 정보를 다시 보는가, 얼마나 자주 보는가
- 다시 보지 않는 이유가 '잊어서'인가, '찾기 어려워서'인가

## 2. 문제 정의

**핵심 문제** `가설`
교육생은 짧은 기간에 쏟아지는 자료를 여러 곳에 흩어 저장하고, 과제나 프로젝트 때 필요한 자료를 다시 찾지 못한다.

**JTBD** `가설`
교육 중 배운 자료가 필요할 때, 어디에 저장했는지 기억하지 않아도 바로 찾고 싶다. 그래서 과제와 프로젝트에 배운 것을 제때 쓰고 싶다.

---

#### 경쟁 가설 — 설문으로 가린다

| 가설 | 다시 안 보는 이유 | 맞다면 핵심은 |
| --- | --- | --- |
| H1 | 어디에 저장했는지 몰라서 못 찾는다 | 찾기 (1차 방향) |
| H2 | 저장한 사실 자체를 잊는다 | 리마인드 (확장 방향) |
| H3 | 저장한 정보를 다시 활용하기 어렵다 | 모아보기 (확장 방향) |
| H4 | 저장은 불안해서 하는 행동이고, 실제로 다시 볼 필요가 적다 | 전제 재검토 |

---

#### 문제 배경 01. 저장하는 곳이 흩어져 있다

교육 중에는 강의 자료, 실습 파일, 아티클, 프롬프트, 회의 기록이 노션, 카톡, 슬랙, 캡처 등 여러 곳에 동시에 쌓인다.

#### 문제 배경 02. 저장한 것을 다시 찾기 어렵다

채널마다 찾는 방법이 다르고, 저장할 때의 맥락이 남지 않아 기억에 의존해 찾아야 한다.

- 예시: 카카오톡 나에게 보내기 (출처: 저장한 콘텐츠를 가치있게, WON)
    - "보통 링크를 카톡에 보내두는데 나중에 키워드 검색으로 찾기 어렵다."
    - "카테고리를 나눌 수 없어서 불편하다."
    - "오래된 내용을 찾으려면 스크롤을 많이 하거나 키워드를 기억해 내야 한다."

#### 문제 배경 03. 저장한 뒤 다시 보지 않는다 `가설`

저장한 정보가 다시 읽히지 않고 쌓이기만 한다. H2가 맞다면 확장 방향(리마인드)의 근거가 된다.

#### 문제 배경 04. 저장한 정보를 재활용하기 어렵다 `가설`

하나의 정보만 확인하는 것이 아니라, 여러가지 정보를 다시 재활용하고 함께 보기가 어렵다. H3가 맞다면 확장 방향(연결)의 근거가 된다.

---

#### 근거 목록

| 주장 | 근거 | 대상 | 등급 |
| --- | --- | --- | --- |
| 저장 위치가 흩어져 다시 찾지 못한다 | 캐릿(2024), WON | Z세대 일반 | 2차 자료 · 교육생 기준 가설 |
| 일단 저장하고 고르는 건 미룬다 | 《트렌드 코리아 2027》 '저장인류' | 일반 | 2차 자료 · 교육생 기준 가설 |
| 카톡 나에게 보내기로는 찾기 어렵다 | 저장한 콘텐츠를 가치있게 WON, 직접 사용 분석 발언 3건 | 일반 | 일화 또는 패턴 |

※ 교육생에 대한 1차 근거는 아직 없다. 설문이 첫 1차 근거다.

#### 설문으로 확인할 것 (행동 기준)

- 최근 한 달 동안 교육 자료를 주로 어디에 저장했나? (배경 01)
- 최근 한 달 동안 저장한 자료를 찾으려다 못 찾은 적이 있나? 그때 어떻게 했나? (H1)
- 저장해 둔 걸 잊고 같은 자료를 다시 검색한 적이 있나? (H2)
- 최근 일주일 동안 저장한 여러자료를 함께 다시 봐야했던 적이 있나? 그때 어떤 어려움을 겪었나? (H3)
- 최근 일주일 동안 저장한 것 중 다시 열어 본 것은 몇 개인가? (H4)

## 4. 서비스 원칙

**1. 저장은 한 번에 끝내고, 그룹 선택은 AI가 돕거나 나중에 한다.**

앱, 웹, 연결된 AI(MCP) 어디서든 저장할 수 있다. 저장 창에서 아무것도 고르지 않아도 바로 저장된다. 

- AI가 기록 내용을 보고 어울리는 그룹을 추천하고, 기본값으로 미리 선택해 둔다.
- 추천이 마음에 들지 않으면 드롭다운에서 다른 그룹을 고르거나 새 그룹을 추가할 수 있다.
- 급하면 건드리지 않고 저장해도 된다. 그룹은 저장 후에도 언제든 수정할 수 있다.
- AI 추천이 없거나 실패한 경우에는 기본 '미분류' 그룹에 들어간다.

**2. 그룹에 넣지 않아도 찾을 수 있게 한다.**

미분류 기록도 AI 챗봇과 연결된 AI(MCP)에 물어서 찾는다.

**3. AI는 내 기록 안에서만 답하고, 출처를 보여 준다.**

내 기록에 없는 내용은 답하지 않는다. 답할 때 찾은 기록이 어느 그룹의 어떤 기록인지 함께 보여 준다.

**4. 저장 이유는 사용자가 원할 때만 남긴다.**

저장 창에서 메모를 남길 수 있지만, 강제하지 않는다.

리마인드, 연결, 재발견·재학습은 설문 뒤 결정한다. (1. 개요 → 확장 방향 참고)

**5. 내용저장 및 원문** 

MVP 범위

- **요약본 저장**: 아티클을 저장하면 AI가 내용을 요약해서 요약본을 기록으로 저장한다.
- **원문은 링크로 저장**: 원문 전체를 가져와 저장하지 않고, 원문 링크(URL)만 함께 저장한다. 요약본에서 원문 링크로 바로 이동할 수 있다.
- 클립보드(글 드레그 후 ctrl+c)로 저장한 텍스트는 AI 요약 없이 선택한 문장 그대로 저장한다. 이때도 출처 링크는 함께 저장한다.

추후 검토 (MVP 이후)

- 원문 전체 저장 방향은 개발 시간이 남으면 검토한다.
- 인스타그램·유튜브·유료 기사처럼 원문 가져오기가 제한되는 경우를 포함해서 검토한다.(스크린샷으로 내용 저장)

## 5. MVP 주요 기능

MVP의 핵심은 쉽고 빠르게 저장하고(1), 쉽게 찾는 것(2)이다. 연결(3)과 리마인드(4)는 확장 방향으로, 구현은 함께 하되 근거는 설문 결과로 판단한다.

| 구분 | 기능 | 우선순위 |
| --- | --- | --- |
| 핵심 | 1. 저장 | P0 |
| 핵심 | 2. AI 챗봇·MCP 찾기 | P0 |
| 확장 | 3. 연결: 모아보기 | P1 · 설문으로 근거 판단 |
| 확장 | 4. 리마인드: 블랙홀 | P1 · 설문으로 근거 판단 |

**디자인 결정**: 설문에서 참여자가 두 시안을 모두 써 보고(같은 과제: 기록 저장하기, 저장한 기록 찾기) 고른 결과, 시안 A(list/space)로 확정했다. A의 가독성에 B의 직관성을 더하는 방향으로 다듬고, Design.md는 시안 A로 통일한다. 결과와 회의 결정은 docs/design-ab-result.md, docs/decisions.md 참고.

### 5-1. 저장 (P0)

저장할 때 분류 부담을 주지 않는다.

- **수집앱 (PC)**: 화면에 로봇이 떠 있고, 누르면 캡처·메모 등 저장 기능이 열린다. 저장한 정보는 우주에 들어간다. 휴대폰에는 수집앱이 없다.
- **웹 (반응형, PWA)**: 반응형 웹에서도 파일이나 기록을 추가할 수 있다.
- **저장 방법**: URL 붙여넣기, 캡처, 클립보드 저장, 파일 추가·끌어다 놓기, 메모
- **클립보드 저장**: 기사를 읽다가 드래그해서 복사한 글을 텍스트로 저장하거나 사진, URL을 저장한다.
- **저장 창**: 어떤 방법으로 저장하든 창이 하나 뜬다.
    - AI가 저장할 정보를 파악해 맞는 그룹을 골라 둔다. 사용자는 그대로 저장하거나 바꾼다.
    - 맞는 그룹이 없으면 사용자가 새로운 그룹 생성
    - 메모는 원할 때만 남긴다.
- **그룹**: 사용자가 직접 만든다.
- **저장 대상**: 정보성 글(URL), 영상(URL), 직접 쓴 메모(txt·md), 이미지(png·jpg·jpeg,svg), HTML, PDF

### **5-2. AI 챗봇·MCP 찾기 (P0)**

행성에 넣지 않은 기록도 물어서 찾는다.

- **AI 챗봇**: 서비스 안에서 내 기록에 대해 묻고 찾는다.
- **MCP**: 평소 쓰는 AI(ChatGPT, Claude 등)와 연결해, 그 AI 안에서 내 기록을 찾고 저장한다.
- **답하는 방식**: 내 기록 안에서만 답하고, 찾은 기록이 어느 행성의 어떤 기록인지 함께 보여 준다.

### 5-3. 연결: 모아보기 (P1 · 확장)

“모아보기“는 기록을 다양하게 엮어서 한눈에 보고, 메모를 추가할 수 있다.

- 기록과 기록을 연결해서 확인하는 그룹 북마크형 기록 모음을 확인하면서 옆이나 아래에서 추가 기록을 남길 수 있게 분할 화면으로 구성한다. (PC는 좌우, 모바일은 위아래)
- 추가 메모는 날짜와 함께 쌓이며 기존 내용을 덮어쓰지 않고 한 기록에 대한 생각이 어떻게 변했는지 시간순으로 볼 수 있다.

### 5-4. 리마인드: 블랙홀 (P1 · 확장)

사용자가 정한 기간이 지난 기록이 생기면 우주에 블랙홀이 생긴다.

- **블랙홀 목록**: 블랙홀에 들어가면 기간이 지난 기록 목록을 볼 수 있다.
- **정리**: 기록마다 지울지 그대로 둘지 정한다.
- **다시 보기**: 목록에서 기록을 누르면 기존 기록 화면이 열리고, 원하면 메모를 남길 수 있다.
- **기간 기준**: 저장한 날로부터 사용자가 정한 기간

## 6. 핵심 사용자 흐름

MVP가 검증할 핵심 흐름은 "저장 → 분류 → 확인 → 연결"이며, 하나의 기록이나 연결된 기록에 새로운 기록을 추가하고, 잊혀진 기록을 다시 확인하는 리마인드 기능으로 “지속적으로 관리” 하는 흐름을 만드는 것을 목표로 한다.

1. **회원가입 및 로그인, 스페이스 생성**
2. **저장**: 아티클을 읽다가 메모하거나 문장을 드래그해서 클립보드로 복사하거나, URL, 스크린 캡쳐, 파일(txt, jpeg, jpg, png, svg, HTML, PDF) 등으로 저장한다. 분류는 나중에 하거나 AI 추천으로 빠르게 분류한다.
3. **AI 자동 분류 및 확인**: 분류 없이 저장했던 기록은 AI가 기존의 그룹 또는 새로운 그룹으로 분류를 추천해준다. 확인은 검색, 직접 리스트 목록 확인, AI 챗봇 안내 또는 알림으로 확인할 수 있다.
4. **연결**: 기록과 기록을 그룹 북마크로 묶어서 묶음 기록으로 확인하고 묶어서 보는 시점에서 다시 새로운 기록과 반응을 추가하거나 자신의 이해도를 추적할 수 있다.
5. **리마인드**: 사용자가 정한 시간 간격 텀에 따라서 리마인드 알림으로 "n일 전에 저장한 글" 을 받아서 확인하고, 필요 없는 기록을 지울 수 있다.

## 7. MVP 범위 밖

아래 항목은 MVP에서 제외하고, 사용자 테스트 결과에 따라 다음 단계에서 검토한다.

| 항목 | 제외 이유 | 다시 검토할 조건 |
| --- | --- | --- |
| 공유 스페이스 (별자리 링크 공유, 다른 사람 기록 가져오기) | 개인 스페이스 서비스 구축 이후 재검토 | 내보내기 사용과 공유 의향이 높게 나옴 |
| 그룹·피드 커뮤니티 | 초기 사용자가 적으면 비어 보이고, 신고·관리 기능 필요 | 공유 스페이스 사용이 활발함 |
| 노션 직접 연동 (OAuth) | 개발량이 큼. MVP는 md 파일 업로드로 대체 | 업로드 단계에서 이탈이 큼 |
| 브라우저 확장 프로그램 | 북마클릿으로 우선 검증 | PC 클립보드 정보 수집이 주요 사용처로 확인됨 |
| AI 자동 주제 제안 | 기록 전체를 읽어야 작동해 서비스 원칙과 충돌 | 정보성 글에 한해 사용자가 켜는 선택 기능으로만 검토 |
| 연간 결산 | 데이터가 쌓여야 의미 있음 | 서비스 운영 1년 후 |
